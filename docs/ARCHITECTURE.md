# ARCHITECTURE — Perigee Fuel Co.

*How the code is laid out and why. Ordinary engineering choices are recorded here; design decisions live in `docs/GDD.md` §22.*

## Layout

| Path | What |
|---|---|
| `Perigee.csproj` | Godot game assembly (`Godot.NET.Sdk/4.7.2`, net8.0). `<Compile Remove="src/**;tests/**;tools/**;build/**" />` keeps the other projects' sources out. |
| `src/Sim/` | **Pure C# simulation, no Godot types.** Deterministic, double precision. Builds and tests headless. |
| `tests/Sim.Tests/` | xUnit tests for every sim system (`dotnet test tests/Sim.Tests`). |
| `game/` | Godot layer: rendering, input, UI, audio. Reads the sim, sends it commands. |
| `tools/` | Headless tools (flight-script runner, sims). |
| `scripts/` | Scripted regression flights (`*.flight`). Test tool only; players get no autopilot. |
| `assets/` | Fonts (OFL, licence beside them), shaders. Art is drawn in code. |
| `docs/` | GDD, STATUS, this file, BALANCE, CREDITS, PLAYTEST, screenshots per milestone. |

`.gdignore` in `src/`, `tests/`, `tools/`, `docs/` keeps the Godot importer out of them.

## Sim (src/Sim)

- **Vec2d / MathD** (`Vec2d.cs`): double 2D vector; angles counter-clockwise from +X, y up.
- **Rng** (`Rng.cs`): xoshiro256** seeded per career; state is four ulongs so it round-trips through saves and every roll replays.
- **Units** (`Units.cs`): 1 day = 6 h game time, 1 year = 400 days, 50 Hz physics step.
- **Orbits/Conic** (`Orbits/Conic.cs`): elements (μ, p, e, ω, Tp, Dir) covering ellipse/parabola/hyperbola and both directions. Position angle θ = ω + Dir·ν. `FromState` ↔ `StateAt(t)` round-trip to 1e-9 (tested). Kepler solvers (`Kepler`): Newton with safe starts and a bisection fallback for ellipses, damped Newton for hyperbolas, Barker closed form for parabolas.
- **Orbits/Patcher** (`Orbits/Patcher.cs`): patched conics. `NextEvent` finds, analytically, the next SOI exit (outbound crossing of r = SOI), active-zone arrival (inbound crossing of atmosphere top / terrain + 2 km) and child-SOI entry. Entry search walks time with a *safe step* = 0.95·(distance − SOI)/(|v_craft| + |v_child|), which cannot step over an encounter, then bisects to 1e-7 s. `Transition` converts the state into the next body's frame; `Predict` chains up to 3 legs for the trajectory preview.
- **Orbits/DeltaV**: Hohmann-through-common-ancestor Δv estimates for market multipliers, scoring and generator checks (not flight guidance).
- **Bodies** (`Bodies/*.cs`): `Body` (GM, radius, rotation, atmosphere, orbit, SOI, radial terrain heightmap, deposits), `Atmosphere` (exponential density), `StarSystem` (parents-first list, per-time position cache, children), `Terrain` (fractal value noise around the circumference; home gets oceans at sea level and a flat 40 m launch plain in the widest land run), `Noise1D`.
- **Craft** (`Craft.cs`): a vehicle = list of `Part`s in the craft frame (x right, y up = nose), attachment tree by part id, staging list, throttle/RCS/legs state, mass/CoM/MoI, modes `Rails` (exact conic), `Active` (50 Hz physics), `Landed` (fixed in the body's rotating frame), `Held` (booster flashback, M5). `Pos`/`Vel` are the centre of mass relative to the SOI body. `Feed()` = tanks an engine can drain (attachment BFS that stops at decouplers/docking ports). `StageReport()` = per-stage Δv/burn time/TWR using the same feed and mass rules the flight sim burns with (gate: within 1% of a simulated burn, tested).
- **Craft/Parts** (`Craft/Parts.cs`): the fixed catalogue (~60 parts, GDD §5/§10 numbers) as `PartDef` data: mass, cost, R&D multiplier, capacities, engine curve (thrust/Isp interpolated by pressure ratio), drag Cd, max temperature, impact tolerance, nodes, flags, procedural art + outline (`Craft/PartArt.cs`).
- **Craft/Design** (`Craft/Design.cs`): a saved rocket (parts with positions/parents/attach kind + stages), JSON round-trip, builder helpers (`Root/Stack/Radial/Pair`), `AutoStage()` (bottom-up by decoupler), and `TestDesigns` (sounding rocket, orbiter with a shield-first capsule, probe).
- **Craft/Flight** (`Craft/Flight.cs`): one active-physics step: propulsion (engines drain feeds proportionally, flame-out on empty; RCS from any tank; reaction wheels + gimbal steer towards a 0.9 rad/s turn rate while a key is held and damp to a stop on release, decision #38), gravity of the SOI body only, aero, heat, symplectic Euler integration, terrain contact (crash above a part's impact tolerance, else land: settle upright within 20°, topple beyond 35°), and the return to rails after 1 s of clean coasting above the active zone (controlled craft must have stopped spinning; debris' spin is dropped).
- **Craft/Aero** (`Craft/Aero.cs`): drag per part on the length of its lateral interval not shadowed by parts in front (sorted along the airflow), depth = part width (fins 5 cm, leg struts 15 cm), transonic bump; flat-plate fin lift `1.1·sin 2α` pushing the plate away from the side the air hits (so fins behind the CoM restore, fins ahead of it destabilise); parachutes open over 1.5 s and tear above their safe speed. `Heat`: flux `K·√ρ·v³` on exposed parts (K scaled for 2 km/s orbits, BALANCE.md), skin heat capacity (15% of part mass, 40 kg floor), heating capped at a scaled stagnation temperature 290 K + v²/1000 (ascent-safe, entry-deadly), radiation, density-scaled convective cooling, ablating shields hold 1,400 K.
- **Craft/InputState + Command**: held controls sampled per tick; edge actions as commands so taps are never lost.
- **Craft/FlightScript** (`Craft/FlightScript.cs`): the scripted-flight harness (test tool only, decision #16): `launch/spawn/active/target/press/release/tap/hold/wait/until/expect/throttle/warp/attitude/approach/descent/periapsis/flyback/skip_booster/recover/droneship/undock/pump/sell/accept/decline/tutorial/shot/view/log/end`, a small expression language over HUD readouts (`ScriptVars`, incl. contract, orbit-timing, target-phase and deposit readouts), an iterator so a Godot host can render between ticks, and `SimHost` (headless). Every script world is `SimHost.NewScriptWorld()` (Standard career, unlimited cash, all parts unlocked) in the runner, the tests and the Godot `--script` mode alike. The helpers press the same keys a player would: `attitude` is a bang-bang hold that leads the target by the stopping angle ω²/2α; `approach` flies to a gate 2.5 m out along the target port's axis and then closes along it; `periapsis` burns pro/retrograde along the inertial velocity (cheap far out) with a gentle last stretch. `spawn … orbit match` copies the active craft's own conic shifted in phase (a circular orbit at the same radius drifts away from a slightly eccentric target); `despawn <name>` removes a craft (test set-up); the state line shows target geometry (`tgt=… d= along= lat= vrel= tspin=`) whenever a target is set. `SimHost.ChargeLaunches` makes `launch`/`spawn` pay the real launch cost (refusing when unaffordable; coreless debris set-ups stay free) and `SimHost.BeforeTick` lets an observer see every tick — both exist for the career model.
- **Drawing safety** (`game/DrawUtil.cs`): every polygon goes through `DrawUtil.Poly`, which drops non-finite/duplicate points, draws sub-2-px slivers (tank stripes at distance) as thick lines instead of asking the triangulator, pre-validates with `Geometry2D.TriangulatePolygon` and warns once per call site; `CraftView.Draw` culls craft whose screen position is off-viewport, because at large offsets float coordinates made every part polygon untriangulable (the Godot log once grew to 630k lines of that error in one replay).
- **Career model** (`tools/CareerSim`, M12 gate): plays one Standard career through the harness with real economics. The tutorial regression script is split into its lessons at runtime (`# ---- Tn` headers); before each mission the model prices its launches and the R&D its designs still need, buys the parts through `BuyRd`, and when the step is unaffordable repeats `scripts/supply-loop.flight` (tanker → depot → 10 t sale, a day of warp between trips so the node's glut clears) until it is — the §23 "repeat supply trips" count. Play time per tick = game seconds ÷ the warp a player would use (hands-on flying 1×, idle physics 4×, rails 100,000×, never slower than the script ran) plus fixed builder/menu overheads; the empty tanker's return is not flown but charged at the measured T5 pad-landing time and refunded at 90% of dry parts. Output: `docs/career-sim.md`.
- **World.Flight** (`World.Flight.cs`): commands, `Launch` (design → landed on a pad), `Stage` (decouplers split subtrees into new craft with a separation impulse; control follows the probe core), `Split`, `DestroyPart` + `ResolveBreakup` (connected components of the surviving attachment tree become their own craft), physics warp 1–4× with 50 Hz substeps, any input on a coasting craft wakes it off the rails. Unloaded craft that reach an active zone are lost (atmosphere) or skipped past periapsis when an airless pass clears the terrain.
- **World** (`World.cs`): clock + crafts + warp. `Advance(dt)` applies rails events in time order and stops the clock exactly on an event of the active craft (warp → 1×). Coasting craft never integrate: their state is a pure function of (conic, t), so warp cannot drift (tested: 1 step of 2 days == 2000 steps).
- **TestSystems**: hand-made star system for tests and demos until the generator (M6).

- **Craft/Docking + World (Docking.cs)**: loaded bubble (2.5 km) decides who leaves the rails; closest approach by sampling both conics then ternary search; ports capture (0.5 m / 5° / 0.5 m/s) → 1 s soft capture (velocities matched) → `Dock` merges the other craft's parts into ours (re-rooted under our port, snapped to exact alignment), claws grab any part; `Undock` splits at the joint with a 0.3 m/s push; `PumpJob`s move a resource at the slowest docked port's rate on the path (2 t/s inside one craft), on rails too.
- **World.Recovery**: booster flashback state machine (`HeldBoosters`, `StartFlashback` rewinds `T`, `IsPresent` hides everyone else, `EndFlashback` restores and catches the rails world up to the landing time), drone ships, refund rates and `Recover`.
- **Economy** (`Economy/Preset.cs`, `Market.cs`, `Economy.cs`, `EconomySim.cs`): `Preset` = the §15 multipliers (starting cash, part prices, upkeep, contract pay, storm/debris rates, market depth, grace days). `Market` holds one node per place a sale can happen (home surface at fixed §10 prices; one low-orbit node per body; a surface node per off-world pad) with the multiplier `M = 1 + 5(e^(Δv/3000) − 1)` from home-surface Δv, a glut that decays with a 10-day half-life, and an exact quote integral so selling 10 t prices every tonne on the falling curve. World partial: `StartCareer` (preset, starter unlocks, cash), R&D unlock by price only (decision #13), `LaunchCost` = parts + propellant, `TryLaunch`, upkeep charged at every day boundary (depots/outposts/pads only), `Runway`, insolvency → grace → `EndCareer`, `NetWorth`/`Score` (net worth + exploration credits), `SellFrom` (drains tanks proportionally; low-orbit sales need a Depot Controller). `EconomySim` is the §2 comparison model (cheapest parametric rocket for a payload+Δv, direct vs depot-refuelled vs mined); its results and the flagged §2 targets are in BALANCE.md.
- **Contracts** (`Economy/Contracts.cs`): `Contract` is plain data (type, client, target body, window/tonnage/count, reward/advance/penalty, deadline from acceptance, progress). `Contracts.Tutorial(n)` builds T1–T10 with fixed objectives, hints and the §11 rewards; `Contracts.Generate` rolls the eight procedural types for bodies you have reached plus the next one out (`ReachableTargets`, by Δv). World partial: the board (`RefreshBoard` at career start and every day boundary: expire offers older than 5 days, top up by 1–3 to 3–6 open; the next lesson is offered the moment the previous one completes), `Accept` (cap 5, optional 20% advance, spawns the client craft), `Fail` (repay advance + 10% penalty), `CheckContracts` once per `World.Advance` (never from memory: every rule reads world state — `Evaluate` per type; hooks `OnDocked`/`OnRecovered`/`OnDebrisDeorbited` set the flags that need an event). Client stations/satellites are real NPC craft (`Craft.Npc`) on rails built from a small design; their parts carry `ClientOf` so fuel delivered into them counts wherever they are docked, and Deploy payloads (`PartFlags.ClientPayload`, free, only in the builder while a contract provides them) are tagged with `ContractId` at launch. A player craft docking with an NPC keeps the player's ownership (`Npc = a.Npc && other.Npc`).
- **Mining** (`Economy/Mining.cs`): an `Outpost` is a landed craft with a working Outpost Core plus every craft landed within 200 m of it on the same body (`World.Outposts()`, rebuilt on demand; production stats are cached per core). `Production(dt)` runs once per `World.Advance` for the elapsed game time, so it works under warp and while you fly elsewhere (GDD §9): drills take from the deposit arcs under the core (one deposit per drill, round-robin when arcs overlap; landing a drill reveals the richness), refineries run their `Recipe` (Auto = methalox › water › metal) with the §8 mass ratios (1 t methalox = 0.45 t water + 0.55 t CO₂; ore → metal at 0.6), everything scaled by power = min(1, generated / needed) where generation = solar × 1/d² (home-orbit radii) × 0.5 night average + RTGs. Output goes to dedicated capacity first, then shared surface tanks (`Part.Room`), and stops when full. Scanning: `OrbitCredit` marks a body `Scanned` after one full orbit by a craft with a scanner. Scoop: in flight, `World.Scoop` collects xenon (giant atmospheres) or CO₂ (CO₂ atmospheres) at `ScoopRate × ρ/3e-11 × v/20 km/s`; giants' atmospheres end in a thin exosphere (ρ ≈ 1e-11 at the rails boundary) so a top-skimming pass is survivable. Electricity in flight: `HasPower` = generation (solar in sunlight — not in the body's 2D shadow — plus RTGs) or a charged battery; `UpdateBattery` runs per physics step. Landed craft get no 50 Hz physics unless they are the active craft with throttle/input or sit inside a flying active craft's bubble: a base on a far moon costs nothing.
- **Pads** (`Economy/Pads.cs`): a `LaunchPad` is an outpost whose modules include a working Pad Kit and a Fabricator (`World.LaunchPads()`); the kit levels the ground around it (`Body.Flatten`, 120 m) so rockets stand and lift off cleanly, and the launch spot sits 30 m downrange of the kit. `PadQuote` = half the cash price + 1.5 t of metal per tonne of dry mass + the propellant the design's tanks hold; `TryLaunchAtPad` refuses without the metal, takes it from the outpost's pooled storage, and fills the tanks from the outpost's stores (partially if short). `World.NodeFor(craft)` is the one place that answers "where can this craft sell": home surface, a low-orbit band, or — landed off-world — the pad-surface node of the outpost it belongs to, where `SellFrom` drains the whole outpost's pool. Recovery within 5 km of a pad pays 90% of the cash share and returns 90% of the metal share plus the unburnt propellant to the outpost's stores (GDD §6); any module but the core can be scrapped that way. Upkeep: $8k/day per Pad Kit (Economy).
- **Hazards** (`Hazards/Hazards.cs`): **debris** = any object without a working core (`Craft.IsDebris`); once a day (`HazardsDay` from the day tick) unloaded debris whose periapsis is below 1.2× the atmosphere height loses a little speed (0.4%/day scaled by depth) until the rails event reenters it; every player craft on rails rolls a hit chance `1 − e^(−Σ rate)` over the debris sharing its altitude band (rate per object 0.006/day × preset × a crossing-speed factor), a hit destroys one random part and the split pieces are new debris (a cascade), and past 2,000 tracked objects a hit destroys but spawns nothing. Inside the loaded bubble `CollisionStep` (after docking) destroys the two closest parts of any two flying craft whose part circles overlap while closing faster than 3 m/s and nudges them apart. **Storms**: a daily roll at `StormRate × luminosity / 40`; `ScheduleStorm(warnDays, durationDays)` puts the world in `Warning` (warp stops, HUD banner, map shadow cones) then `Active`; `StormStrike` runs at the start and at each day boundary of the storm for craft not yet struck: sheltered = landed, inside a body's 2D shadow (`InShadow`) or within home's magnetosphere (absolute distance); otherwise hardened parts are immune, depot/outpost controllers go offline 5 days, standard cores fry with 25% (`StormFryChance`, forced to 1 by tests) for 3–5 days. `Part.Offline/OfflineUntil` are cleared by `StormStep` when the time passes; `Craft.HasControl` ignores offline cores, so a fried craft rides the rails (`Craft.Fried` for the HUD).
- **Save** (`Save/SaveData.cs`, `Save/Save.cs`): `World.ToSave()` copies every field that cannot be recomputed into plain DTOs (`SaveData` → nodes, contracts, craft with parts/rails/landed/capture/pumps, mutable body bits — scanned, revealed deposits, flat spots — held boosters, drone ships, storm state, Rng state as four ulongs, career counters); `World.FromSave` regenerates the star system from its seed (or the hand-made test system) and rebuilds the rest. `SaveStore` is JSON + gzip with a `Version`, a `Migrate` hook, atomic writes (`.tmp` then rename, previous file kept as `.bak`) and `ReadOrBackup`. Saving during a booster flashback is refused (transient by design). `World.StateHash()` is a bit-exact FNV fingerprint used by the round-trip and determinism tests. The game layer (`game/Careers.cs`) keeps one file per career at `user://careers/<slug>.pfc` and autosaves on the sim's `SaveRequested` flag (launch, landing, docking, recovery, purchase, warp stop, sale, contract completion; throttled to one per 5 s), every 3 real minutes and on quit; dev/demo/script worlds never save.
- **Stuck careers** (`Economy.cs` `IsStuck/CheckStuck`): the brief requires no soft-lock short of bankruptcy, and the GDD's game-over rule only fires at $0. A career with cash above zero but below the cheapest launch, no earning craft, no accepted contract, no outpost and no depot stock, whose open offers' advances cannot close the gap, is "stuck"; after the preset's grace days it ends like insolvency ("stuck: could not fund a launch"). HQ Finances and a warp stop explain it while the grace runs.
- **Generator** (`Generator/SystemGenerator.cs`, `Names.cs`): deterministic per seed (one `Rng` forked per stage); spacing enforced analytically (Hill radii, SOIs, Roche); guarantees applied after the fact (enrich the cheapest landable body, or add a near-home asteroid); `SystemValidator.Check` is the 1,000-seed gate.

## Game layer (game/)

- **Main**: arg parsing (`--screenshot`, `--frames`, `--selftest --save`, `--script=<file> [--shots=dir] [--fast]`, `--design`, `--zoom`, `--time`, `--focus`, `--warp`, `--nomsaa`), samples held keys into `World.Input` once per 50 Hz tick, routes taps to `World.Apply`, and advances the world by `dt × EffectiveWarp`. Script mode steps the `FlightScript` iterator (200 steps/frame with `--fast`), pausing for `shot` captures.
- **GodotHost**: `IScriptHost` through the real input path (`Input.ParseInputEvent` for held actions, `_UnhandledInput` for taps).
- **CraftView**: part polygons with flip, plumes widening as pressure drops, open canopies, reentry glow from heat flux, hot parts tinted; sub-pixel art skipped (degenerate polygons fail triangulation). Craft under 14 px draw as a chevron.
- **FlightView**: floating-origin renderer. Every position is computed in doubles relative to the focus; only screen pixels go to Godot. One continuous zoom (1.5e-8 … 400 px/m). Draw order: background+stars (its own `_Draw`) → atmosphere glow (`ColorRect` + `assets/shaders/atmo.gdshader`, per-pixel exponential falloff from up to 8 bodies) → `SceneLayer` (orbits, bodies, craft, prediction, labels). Bodies smaller than 2.2 px are dots; discs up to 5,000 px are full terrain polygons; larger ones draw only the visible arc (angular window of the screen as seen from the body centre) with the sea band first and the terrain band on top so water fills basins. Conics sample uniformly in true anomaly, restricted to the visible window when the orbit dwarfs the screen. Labels go through a queue that pushes overlapping labels down.
- **Hud**: date/warp/focus, ALT / surface+orbital speed / VS / AP / PE / Q, throttle bar, stage counter, RCS, per-stage Δv/burn/TWR, fuel bar, heat warning, scale bar, event log, last script line.
- **View rotation**: at flight scale (≥ 0.02 px/m) the view turns so local up is screen-up; at map scale (≤ 0.002) north is up; blended in between. Orbits and rotations in the test system run clockwise so "prograde" reads rightward with the planet below.
- **Controls**: input actions created in code (GDD §4 table).
- **Pal**: §17 palette and the Noto fonts.

## Career flow (game/Main.Career.cs, Screens.cs, HqScreen.cs, Profile.cs)

A plain launch shows the **title** (New Career · Continue · Settings · Quit, personal bests per preset from `user://profile.json`); any dev argument (`--demo`, `--seed`, `--design`, `--builder`, `--screenshot`, …) keeps the old demo world, `--script` runs the harness, `--career=<file>` continues a save. **New career** = agency name + preset → a fresh generated system from a random seed (stored, never shown) → `StartCareer` → first autosave. **HQ** (H, or from the pause menu) is a `TabContainer`: the contract board node itself moves into the Contracts tab while HQ is open; Market draws each node's prices with 30-day sparklines from `Market.History`; R&D lists every part with a confirmed Buy; Finances shows cash/runway/upkeep breakdown, insolvency or stuck days and a 60-day cash graph; Logistics lists depots, outposts and pads with stock, production, power, upkeep and offline state; Score shows the live breakdown, peak and personal best. **Pause** (Esc) freezes the sim (`MenuOpen`) with resume/HQ/settings/save-and-quit. **Settings**: per-bus volume (buses Master/Music/SFX/UI exist from the start), fullscreen and window size, UI scale (`ContentScaleFactor`), key rebinding per action (stored in the profile, applied to `InputMap`; reset restores `Controls` defaults). **Confirmations** (`Main.ConfirmThen`) guard R&D purchases and contract advances; tests and scripts bypass the modal. **Tooltips**: the HUD registers a rect + text for every readout it draws and shows the one under the mouse. **End of career**: the logbook (days, peak score, bodies reached, launches/recoveries/dockings, contracts, money, storms) records the personal best and offers New Career / Title.

## Renderer

Mobile (Vulkan) with 2D MSAA ×4, verified on the RTX 2070 SUPER (`docs/screenshots/M0/probe-msaa4.png` vs `probe-nomsaa.png`: 6,254 vs 3,405 antialiased edge pixels).

## Conventions

- Sim coordinates: metres, seconds, kilograms; money in cents (long). Angles in radians, counter-clockwise, +Y up. Screen conversion flips Y.
- Bodies are added parents-first (the star is id 0).
- Rails events: `Patch.End` ∈ {ExitSoi, EnterSoi, ActiveZone, Horizon}.


## M13 — audio, achievements, performance, exports

- **Audio** (`game/Audio.cs`, assets from `tools/audio/build.py`): four 32-second music loops in one key start together and stay in phase; the mix is a pure function `Audio.Mix(world, paused)` → per-loop levels (orbit pad always; launch swell while thrusting in the first 150 s after launch; docking pulse with a target inside the loaded bubble; storm motif during Warning/Active; everything silent when the career is over or insolvent). Engine: `engine_air` at throttle × √pressure-ratio and `engine_vac` at throttle × (1 − √pr) × 0.7, pitch 0.85–1.15 with level; pump and reentry loops from the active craft's pump jobs and hottest part. One-shots come from `SimEvent`s (staging, docking, undocking, touchdown, crash/part loss, recovery → cash) and from state transitions the sim does not announce (legs, chute opening, storm warning, contract completion, sales). Test runs mute the master bus. `uv run --with numpy python3 tools/audio/build.py` regenerates everything deterministically; `godot --headless --path . --import` afterwards.
- **Achievements** (`game/Achievements.cs`, `game/Platform.cs`): the 20 §19 ids/titles are data; conditions read `World` (career stats incl. the new `refined_methalox`, `pad_launches`, `xenon_scooped`, `storms_clean`, `booster_streak` counters — the streak and `LastBoosterDesign` are kept by `Recover` and saved). `Main.UnlockAchievements` runs every 2 s of career time, records ids in the profile, calls `IPlatform.Unlock` and shows a HUD toast. `SteamPlatform` only does real Steamworks calls under the `STEAMWORKS` compile symbol; otherwise `LocalPlatform` is used and the game never needs Steam.
- **Performance** (`--bench`): three scenarios measured with vsync off and sim/draw timing split. The fixes that took scenario B from 15 to 111 fps: `World.Active` caches the lookup (it was a list scan per call and `NearActive` called it per craft), `Craft.StateAt` memoises the last (instant, rails) solve, `LoadedCrafts`/`UpdateBubble` skip rails craft whose conic never comes within a bubble of the active radius (`CouldBeNear`), part fills are one `CanvasItemAddTriangleArray` per craft (fan triangulation; PartArt shapes are convex) and debris marks one array for all of them (`DrawUtil.Dots`).
- **Exports**: `export_presets.cfg` (Linux x86_64, Windows x86_64; `.flight` scripts included so the build can run its own regression flights), `tools/build.sh` → `build/<platform>/` + zips in `build/dist/` with the licence files. `config/version` is the release tag. `Perigee.sln` must exist: without it the .NET exporter logs "no solution file was found" and writes a binary with no `data_Perigee_<platform>/` folder, which segfaults at boot.
